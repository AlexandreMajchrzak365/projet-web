# Projet web

Projet individuel du module Développement web, classe 3MOCINF1, Gymnase du Bugnon.

Un site qui fait découvrir **quelque chose que vous connaissez bien** à **un public précis**.

- Le cahier des charges complet, le calendrier et la grille : onglet **Le projet** du [portail de la classe](https://erdnaxelakazrhcjam.github.io/portail-3mocinf1/projet.html).
- Le site publié : `https://votre-pseudo.github.io/projet-web/`

## Ce que contient ce dépôt

| Fichier ou dossier | Rôle |
|---|---|
| `index.html` | La page d'accueil : GitHub Pages l'affiche en premier |
| `style.css` | La seule feuille de style de tout le site |
| `script.js` | Le JavaScript de tout le site |
| `img/` | Vos images |
| `maquette/` | Les photos de votre maquette papier |

## Cahier des charges (minimum)

**Structure**
- Au moins 3 pages HTML reliées par un menu commun, avec `index.html` comme page d'accueil.
- `header`, `nav`, `main` et `footer` sur chaque page.
- Une version anglaise de chaque page, dans un fichier à part (par exemple `index-en.html`), et un lien FR / EN sur chaque page.

**Contenu**
- Au moins 4 images, chacune avec un `alt` utile.
- Une vidéo YouTube intégrée.
- Les sources des images, des polices, des chiffres et des faits.
- Aucune donnée personnelle, ni photo d'une personne sans son accord.

**Style**
- Une seule feuille `style.css`, avec des règles sur des balises et sur des classes.
- Un contraste suffisant entre le texte et son fond.
- Un site lisible sur un téléphone.

**JavaScript**
- Au moins 2 interactions que vous savez expliquer.
- Un site qu'on peut parcourir au clavier (touche Tab).

**UX**
- Aucun dark pattern… sauf un seul, volontaire, que vous savez nommer et expliquer.

**Publication**
- Le site est en ligne sur GitHub Pages, et son lien figure sur le portail de la classe.

## Évaluation

| Bloc | Poids |
|---|---|
| Maquette | 15 % |
| Site final | 35 % |
| Commits | 15 % |
| Oral | 35 % |

## Règles

- Le projet se fait en classe.
- Un commit par étape, avec un message clair.
- L'IA est autorisée si vous la déclarez dans le message du commit et si vous savez expliquer chaque ligne.
- Pas de framework, de CMS ni de constructeur de sites.
- GitHub refuse les fichiers de plus de 100 Mo : les vidéos vont sur YouTube, pas dans le dépôt.
- Le site est public : tout ce qui est dans le dépôt est visible par tout le monde.
